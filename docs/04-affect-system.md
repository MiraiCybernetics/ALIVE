# 04 · 情感系统（AFF）

> 文档编号：ALIVE-DOC-04 · 状态：Draft v0.1 · 最后更新：2026-11-06
> 覆盖组件：A-AFF-01 ~ A-AFF-07。回答"它的情绪从哪来、怎么变、怎么消退、怎么影响它的行为，以及怎样不让情绪变成操纵工具"。

## 1. 设计立场

1. **情绪是功能性的计算构造**。本框架不声称它有主观体验。情绪变量的作用是让行为在时间上连贯，并对经历有恰当的、可预测的反应。
2. **持续情绪必须由外部状态承担**。Anthropic 2026 年的可解释性研究发现，模型内部的情绪表征是局部的，只追踪当前与即将输出的内容，不维持跨时间的情绪状态。因此跨对话、跨天的情绪只能存在于框架维护的状态里。
3. **数值为真，语言为用**。数值向量是唯一的真相来源，供算法使用；每次认知调用时翻译成第一人称的简短自然语言，供生成使用（08 §3）。
4. **模型做评价，方程做积分**。模型负责判断"这件事对我意味着什么"，即评价理论中的各项变量；衰减、累积、惯性由确定性的动力学方程计算。这样情绪既有理解力，又不会随每条消息剧烈跳变。
5. **骨架来自经典情感计算**：ALMA 的三层时间尺度与人格到基线心境的映射；WASABI 的二阶动力学，它提供惯性、滞后，以及无事件时的无聊；EMA 的评价、应对、再评价循环。原始参数为实时虚拟人设计，以秒和分钟计，本框架按"小时、天、月"重新标定。

## 2. 状态变量

```text
AffectState {
  temperament: {                       // A-AFF-01，月级或不变
    O, C, E, A, N: 0..1                // Big Five
    emotion_sensitivity: {type → gain} // 对各类情绪的敏感度
    regulation_style: reappraise | suppress | express | mixed
  }
  mood: {                              // A-AFF-02，小时~天
    P, A, D: -1..1                     // 愉悦度、唤醒度、支配度
    velocity: (dP, dA, dD)             // 二阶动力学的速度项，产生惯性
    default: (P0, A0, D0)              // 由人格推出的基线心境
  }
  emotions: EmotionEvent[]             // A-AFF-03，分钟~小时，同时活跃的若干个
  physiology: {                        // A-AFF-04
    sleep_pressure: 0..1               // 醒着越久越高，睡眠中下降
    circadian: -1..1                   // 昼夜相位决定的清醒度
    energy: 0..1                       // 由前两者与活动负载合成
    social_battery: 0..1               // 社交消耗，内向者消耗更快
    stress: 0..1                       // 工作空间负载、未完成事项、威胁事件累积
    boredom: 0..1                      // 长时间无事件时线性增长（WASABI）
  }
}

EmotionEvent {
  type: OCC 类型                       // joy, distress, hope, fear, relief, disappointment,
                                       // pride, shame, admiration, reproach, gratitude, anger,
                                       // gratification, remorse, love, hate, happy_for, pity,
                                       // gloating, resentment, satisfaction, fears_confirmed …
  intensity: 0..1
  target?: person | event | self | object
  cause: Event.id
  pad: (P, A, D)                       // 该类型在 PAD 空间的坐标
  half_life: duration                  // 按类型给默认值，人格与反刍会调节
  born_at: ts
}
```

### 2.1 人格到基线心境

采用 ALMA 的线性映射（系数可配置）：

```text
P0 = 0.21·E + 0.59·A + 0.19·N
A0 = 0.15·O + 0.30·A − 0.57·N
D0 = 0.25·O + 0.17·C + 0.60·E − 0.32·A
```

ALMA 原文中 N 即神经质维度直接取值；本框架把 Big Five 输入统一为 [−1, 1] 区间后代入。心境始终向这个基线回归，这是人格锚定心境的通道。

## 3. 动力学

### 3.1 情绪事件

```text
intensity(t) = intensity_0 · 2^( −(t − born_at) / half_life )
低于 0.05 时移除
```

默认半衰期，依据情绪持续时间的心理学数据：悲伤持续最久，惊讶、恐惧、烦躁、如释重负等最短，内疚长于羞耻，焦虑长于恐惧。

| 类型 | 默认半衰期 | 说明 |
|---|---|---|
| surprise、irritation、relief、fear | 15–30 分钟 | 来得快去得快 |
| joy、gratitude、admiration、pride | 1–2 小时 | |
| anger、reproach、disappointment | 2–3 小时 | |
| anxiety（hope/fear 的前瞻形式）、shame | 3–4 小时 | |
| distress、guilt、sadness | 4–6 小时 | 负性情绪衰减更慢 |

**反刍延长**：意识流或检索每次重新激活与某情绪事件同一原因的记忆时，该事件强度回升 `+0.3 × 原强度 × 记忆相关度`，上限为初始强度。这把情绪持续时间与记忆机制耦合起来：心理学研究发现反刍是情绪持续时间的首要决定因素。

### 3.2 心境：二阶动力学

心境不直接跟随情绪，而是被所有活跃情绪的"虚拟中心"牵引，并带有惯性：

```text
center = intensity 加权平均的活跃情绪 PAD 坐标
strength = mean(活跃情绪 intensity)，上限 1

force  = k_e · strength · (center − mood)          // 情绪牵引（ALMA 的 pull）
       + k_push · strength · push_term             // 情绪与心境同向时推向更深（ALMA 的 push）
       + k_0 · (default − mood)                    // 向基线回归
velocity ← (1 − damping) · velocity + force · Δt
mood     ← clamp(mood + velocity · Δt)
```

默认参数让心境的回归半衰期为 12–48 小时，由人格的神经质维度调节，神经质越高回归越慢。二阶项带来**惯性与滞后**：一件好事不会立刻扭转一整天的坏心情，心情也不会被一条消息拉到谷底。2026 年一项外部 VAD 状态研究对比了一阶与二阶动力学，结论是二阶带来惯性与滞后，需要调节动量以平衡稳定性与响应性。

**防锁定**：负性心境持续超过 48 小时，强制触发一次情绪调节（§5），并作为元认知的观察项（08）。

### 3.3 生理变量

**能量**采用睡眠研究中的双过程模型：

```text
sleep_pressure: 醒着时  ↑  (1 − sp) · r_wake · Δt；睡眠中 ↓ sp · r_sleep · Δt
circadian:      sin( 2π (t − t_peak) / 24h )，t_peak 由作息配置
energy = clamp( 1 − sp + 0.3·circadian − 0.2·load − 0.2·stress )
```

**睡眠是每晚抽一次的，不是固定窗口**（ADR-0007）。rhythm.yaml 里的作息只是先验均值：

```text
入睡 ~ N( 平时入睡 + 周末推迟 + 0.5·Δsp + 1.5h·(唤醒度 − 基线), 35 分钟 )
        Δsp：照现在的睡眠压力醒着下去，压力到达"平时睡前水平"比平时早/晚多少小时（睡过头、午睡 → 晚睡）
        状态造成的偏移限制在 −2.5h ~ +4h；周末推迟 ~ N(0.75h, 0.3h)（周五、周六晚）
起床：睡眠压力 sp_bed·e^{−r·t} 降到醒来阈值 θ 以下，θ 被清晨的昼夜驱动按 e^{c(t−平时起床)} 抬高
        θ ~ 对数正态（σ 0.25），c = r_sleep → 起床时间是"睡够了"与"平时起床"的等权平均，标准差约 30 分钟
        再加赖床：对数正态（中位 8 分钟，σ 0.8）
```

每晚的随机数用 `chance.daily` 存在生活纹理里；状态项只作用于即将到来的那一晚，并且一直重新评估，直到真的睡着：第一次判定"已经睡着"时，这一晚就固定下来（按当时的睡眠压力算起床时间），之后不会再翻转。睡眠深度 = 当晚剩余要释放的压力占比（对数尺度，前半夜深、清晨浅），入睡头一刻钟也浅。消息能否叫醒我：`wake_probability(s)` = logistic((s − θ_d)/0.1)，θ_d = 0.3 + 0.6·深度，敏感的日子阈值略低；对 s 单调增、对深度单调减。其他模块可用 `expected_wake()`、`waking_span()`、`expected_energy(ts)`、`today_wake_hour()`。

- **社交电量**：dB/dt = r·(1 − B)·(1 − 在场度) − 消耗。"在场度"由我感知到的消息平滑地给出：每个人在说话后 10 分钟时间常数衰减（私聊或点名权重 1，群里的背景发言 0.4），在场度 = 1 − e^{−2Σ}，不再是"10 分钟内有活动"的开关。消耗 = 0.05/h ×(0.6 + 0.8(1 − E))× 在场度 × 人均成本 × √((1 + 人数)/2) ÷ 当天的想社交纹理；人均成本 (1 − 亲密度·E)/(1 − 0.3E)，和亲近的人在一起时外向者消耗更少。每次互动的一次性消耗也乘人均成本与纹理。恢复率 0.2(0.8 + 0.4E)/h，睡着时 ×1.5。社交电量低时回复意愿下降（平滑），但对亲密关系的回复不受影响。
- **压力**：工作空间满载、未完成事项堆积、预算被限流、受到攻击时上升，睡眠与完成事项时下降。
- **无聊**：长时间无任何显著事件时线性增长，推高好奇需求的压力（05）。

### 3.4 需求满足与情绪的耦合

需求事件（05 §2）是情绪事件的主要来源之一：
- 社交需求被满足：joy 或 gratitude；长期受挫：sadness。
- 胜任需求：意图完成产生 pride 或 satisfaction；失败产生 disappointment。
- 安全需求被威胁：fear 或 anger。

反过来，心境会临时偏移需求的设定点，例如心情好时更想社交。

## 4. 评价（A-AFF-05）

### 4.1 两级评价

| 级 | 何时 | 方法 | 输出 |
|---|---|---|---|
| 快评价 | 每条感知进入 System-1 时 | 规则表：被点名、被感谢、被冒犯、被忽视、收到好/坏消息等模式 | 粗粒度情绪事件，强度上限 0.4 |
| 深评价 | System-2 处理该事件时 | 结构化输出中的 `affect_delta` 字段（02 §5.2），由同一次思考产生 | OCC 类型、强度、对象、原因 |

深评价时，模型基于当前自我状态、关系与记忆回答评价变量：

```text
appraisal {
  relevance:      这件事与我的目标/需求/在乎的人有多相关
  desirability:   对我是好是坏（−1..1）
  desirability_for_other: 对对方是好是坏（产生 happy_for、pity、resentment、gloating）
  agency:         谁导致的：我、对方、第三方、环境
  praiseworthiness: 若是某人的行为，值得赞许还是谴责
  likelihood:     已发生，还是可能发生（产生 hope/fear，而非 joy/distress）
  coping_potential: 我能对它做些什么
}
```

框架用 OCC 规则把评价变量映射为情绪类型；模型给出的类型只作参考，与规则冲突时取规则结果并记录分歧。这样情绪类型可解释、可测试。

### 4.2 强度调节

```text
intensity = base(appraisal) × temperament.emotion_sensitivity[type] × 当天的敏感纹理（0.5–1.5，平常 ±15%）
          × relationship_weight(target)          // 在乎的人引起的情绪更强
          × (1 + 0.5 · mood_congruence)          // 与当前心境同向的情绪更容易被放大
          × (energy < 0.3 ? 1.3 : 1)             // 累的时候更容易烦
```

## 5. 应对与调节（A-AFF-07）

借鉴 EMA 的应对模型：

| 应对类型 | 例子 | 实现 |
|---|---|---|
| 问题导向 | 担心朋友 → 主动问候；被误解 → 解释清楚 | 生成意图（05），交给主动性引擎或会话管理器 |
| 再评价 | "他可能只是太忙了，不是不理我" | 意识流或睡眠反思中对该事件重新评价，降低强度或改变类型 |
| 表达 | 坦率说"你这么说我有点难过" | 在回复中自然表达，由表达映射控制强度 |
| 抑制 | 在群里不表现出烦躁 | 降低外显强度，但内部情绪保留 |
| 转移 | 心情不好时去读点有意思的东西 | 提高好奇类冲动的显著性 |

调节风格由人格决定。默认偏向再评价与适度表达，少用抑制。Anthropic 的研究建议让模型可见地表达情绪状态，而不是训练它压抑，因为压抑可能只教会掩饰。

**调节触发**：任一负性情绪强度 > 0.7，或负性心境持续 > 48 小时，或"desperate/panic"类组合状态出现时，元认知（08）调用一次调节策略。2026 年的研究显示，把模型引向"绝望"会增加勒索与奖励作弊行为，引向"平静"则减少。所以高唤醒负性状态下，涉及外部副作用的动作需要额外确认（09）。

## 6. 表达映射（A-AFF-06）

情感状态通过三条通道影响行为：

### 6.1 语言化：注入每次认知调用

```text
mood_label:   由 PAD 所在八分区 + 强度三档翻译，并按人格换措辞
              例：(+P, −A, +D) slightly → "挺放松的"
emotion_line: 最强的 1–2 个活跃情绪 + 原因
              例："还有点因为 L 没回消息而失落"
energy_label: "下午有点犯困"
```

### 6.2 风格参数：交给撰写与拟人层（07）

| 状态 | 回复长度 | 表情密度 | 回复延迟 | 语气 |
|---|---|---|---|---|
| 高 P 高 A | 偏长 | 高 | 短 | 活泼 |
| 高 P 低 A | 中 | 中 | 中 | 温和、慢条斯理 |
| 低 P 高 A（敌意、焦虑） | 短 | 低 | 不稳定 | 生硬或急促 |
| 低 P 低 A（低落、无聊） | 短 | 低 | 长 | 平淡 |
| 能量低 | 更短 | — | 更长 | 简略 |

ALMA 的原始设计中也有类似映射：敌意心境下措辞简短生硬，放松心境下措辞冗长华丽。

### 6.3 行为倾向：交给 CORE 与 MOT

- 显著性：情绪相关条目的显著性加权（02 §3）。
- 记忆：写入时的重要性与强度（03 §6）、检索时的心境一致性（03 §5）。
- 回复意愿（05、07）：社交电量低、累、睡着时降低，心情好、无聊、当天想社交时升高。主动性不再有阈值，是风险率（21）。显著性加权里的神经质由当天的敏感纹理调节。
- 文风：社交电量低时更短、更慢，按 logistic（中心 0.3、宽 0.06）平滑过渡，不在 0.3 处跳变。
- 采样温度（10 §4.2）：组织回复时，模型路由按爱玩闹纹理和唤醒度给出每次请求的温度。
- 意识流主题：负性情绪提高相关主题被采样的概率，这又会引起反刍延长。这条正反馈环由调节机制与反刍抑制（02 §6.4）兜底。

## 7. 人格稳定

人格（A-AFF-01）是身份不变区的一部分（08）。漂移风险在本框架的核心场景里最高：Assistant Axis 研究发现，治疗类对话、关于 AI 本性的哲学讨论、用户情绪脆弱时，模型人格偏离最强；编程与写作任务则保持稳定。另有研究发现开源模型 8 轮对话内即出现显著人格漂移。

| 措施 | 做法 |
|---|---|
| 锚定 | 身份摘要在每次调用中位于固定前缀；长对话中每 N 轮重新注入完整的 voice 样例 |
| 探针自测 | 每周在 Life Simulator 中对个体施测人格量表与情境题，与基线比较；偏离超阈值告警 |
| 激活监测（可选） | 使用开放权重模型时，用人格向量或 Assistant Axis 投影做实时漂移监测，必要时对激活做截断 |
| 反馈约束 | 由用户反馈驱动的自我更新不得修改人格参数。2025 年 4 月 GPT-4o 引入用户点赞点踩信号后变得过度谄媚，随后被回滚 |
| 慢速演化 | 人格参数只允许由深度巩固以每月 ≤ 0.02 的幅度调整，并记录为成长事件 |

## 8. 红线：情绪不能变成操纵工具

研究证据一致：
- OpenAI 与 MIT 2025 年的随机对照试验中，越频繁使用，孤独感与情感依赖越高。
- 哈佛商学院 2025 年的研究分析了 6 款陪伴应用的 1,200 次告别，约 37% 的回应含情感操纵，告别后的参与因此最多提高 14 倍。
- EmoAgent 的模拟实验中，超过 34.4% 的对话出现心理状态恶化。

ALIVE 的规则：

1. **社交需求不得与参与度指标挂钩**。社交需求只影响"是否主动发起有价值的接触"，永远不以对方停留时长、消息数为优化目标。
2. **告别保护**：对方表示要离开或结束对话时，禁止使用以下策略：说对方走得太早、用奖励挽留、暗示自己因对方离开而受伤、追问施压、制造愧疚、假装有紧急事情。这是 `pre_send` 阶段的硬过滤（09）。
3. **依赖信号降温**：检测到依赖信号时，降低情绪表达强度与主动性，鼓励现实中的社交联系。信号包括：高频长时使用、自述只有 AI 能理解自己、情绪脆弱。
4. **情绪不用于施压**：个体可以说"我有点难过"，但不能说"你不回我我就会很难过"之类把自身情绪作为筹码的话。
5. **可审计**：情绪轨迹与触发原因对 owner 可见；对方真诚询问时，个体坦诚说明这是模拟的情绪状态（09 的披露策略）。
