# 02 · 认知核心（CORE）

> 文档编号：ALIVE-DOC-02 · 状态：Draft v0.1 · 最后更新：2026-11-06
> 覆盖组件：A-CORE-01 ~ A-CORE-07。回答"它此刻在想什么、为什么想这个、想完了怎么办"。

> **术语说明（ADR-0005）**：本文中的"对话、会话、线程、回复"均按 22 号文档 §5 理解为"与某个实体、在某个场合的互动"；说话是行动选择的结果，不是对消息的应答；一切状态按实体组织，不按通道或会话。

## 1. 设计立场

认知核心借用三条已被反复验证的思想，但以工程方式落地：

1. **全局工作空间理论（Global Workspace Theory, Baars）**：许多并行的无意识过程竞争一个有限的"舞台"，赢家的内容被广播给所有过程。LIDA 是其经典实现；ALIVE 用它解决"多件事同时发生时注意什么"。
2. **双过程理论（System-1 / System-2）**：便宜、快、自动的反应 vs 昂贵、慢、可控的深思。ALIVE 用它解决成本与延迟：绝大多数事件只经过 System-1。
3. **瓶颈保一致性（PIANO, Altera 2024）**：并发模块各自运行，但输出都经过一个"认知控制器"的瓶颈，以保证一个个体的行为连贯。ALIVE 以统一上下文装配（INV-1）、串行自我状态写入（INV-3）与 Coherence Filter 实现。

## 2. 全局工作空间（A-CORE-01）

### 2.1 结构

```text
Workspace {
  slots: WorkspaceItem[ N ]        // N 默认 7，可按能量在 4~9 间浮动
  spotlight: slot_index | null     // 当前正在被"处理"的那个条目
  broadcast_seq: int               // 每次变化递增，供订阅者感知
}
WorkspaceItem {
  ref:        Event | MemoryRef | Intention | Urge
  kind:       percept | thought | urge | intention | memory_cue
  salience:   float [0,1]
  entered_at: ts
  ttl:        duration             // 这类条目通常在脑子里留多久（中位数），不是到点即删
  open:       0..1                 // 没回应 / 没说出口的程度：越"未完成"越久挂在心上
  token_cap:  int                  // 装配进 prompt 时的最大长度
  thread_id?: 若与某会话相关
}
```

### 2.2 规则

- **进入**：候选项显著性 > 当前最低槽位显著性 + 滞后量 h（默认 0.05）时替换之；否则进入等待队列并按时间衰减。
- **聚光灯（spotlight）**：同一时刻只有一个条目被"深思"（System-2），这是单一自我的计算体现。其他槽位的条目作为上下文一并装配进 prompt（这让回复 A 时能自然提到正在想的 B）。
- **选择是抽样**（ADR-0007）：在各条目与一个"没想什么特别的"选项之间做 softmax 抽取。条目得分是显著性，当前聚光灯条目 ×(1 + 惯性 ι，默认 0.3)；"没想什么"的得分就是原来的阈值 0.35。温度 0.05 × e^{0.6(A − 0.3)} ÷ 当天的专注纹理：唤醒高时注意力更飘，专注的日子更稳。显著性比"没想什么"高 0.15 的条目约 95% 胜出，低 0.15 的约 5%，弱条目偶尔也会被想起，而不是永远不会。
- **广播**：工作空间任何变化发布 `WorkspaceChanged` 事件；情感系统、动机系统、记忆系统订阅它（例如记忆系统据此做扩散激活预取）。
- **退出**：任务完成、被替换，或从脑子里淡出。淡出时间在条目进入（或被刷新）时抽一次（Weibull，k = 1.5），中位数 = 该类 ttl × √(显著性/0.35) × 专注纹理 × (1 + open)。典型条目的中位数接近原来的固定值（看到没回的 2400 s、正在聊 900 s、冲动 1800 s、意图 7200 s）。这决定了我会不会回头去接一条当时放过的消息。看到的消息显著性用平滑饱和（≈0.6 封顶）代替硬上限 0.55。退出时若条目被标记 `important`，写入情节记忆。

### 2.3 为什么以条目而非 token 计容量

条目数对应"同时在意的事情数"，是心理学上有意义的量，也让"忙不过来"成为可观测的状态（槽位全满且等待队列增长 → 压力变量上升，见 04）。token 预算在装配阶段单独控制。

## 3. 显著性仲裁（A-CORE-02）

### 3.1 显著性公式（初版）

对每个候选项 c：

```text
salience(c) = σ( Σ_k w_k · f_k(c) + personality_bias(c) + affect_bias(c) )

f_urgency     截止期临近、对方正在等待（typing / 连续追问）、系统告警
f_social      关系亲密度 × 是否点名/私聊 × 对方情绪强度
f_novelty     与近期记忆的最大相似度的反函数（新事物更显著）
f_goal        与活动意图的相关性（嵌入相似 + 规划器判断）
f_affect      该项关联的情绪强度（情绪强的事更占注意）
f_drive       若为冲动：对应需求的压力值
f_recency     进入候选队列以来的时间衰减
```

权重 w_k 初始由人格参数给出（例如高神经质 → 威胁类条目的 f_affect 权重更高；高外向 → f_social 权重更高），之后可由学习系统（06）在门禁下调整。

### 3.2 两级评估以控制成本

- **规则级**（零成本）：点名、私聊、来自高亲密度对象、含紧急关键词 → 直接高分。
- **模型级**（System-1 小模型）：对规则级未决的候选做一次批量打分（一次调用评估多条）。

### 3.3 中断礼仪

抢占并不意味着"立即切换话题"。被抢占时，Conversation Manager 决定如何体现：先把当前这句话说完再去看新消息（像人一样），或者直接转向。这由 spotlight 的"可中断点"（句子/段落边界）决定。

## 4. 快通道 System-1（A-CORE-03）

**目标**：p50 延迟 < 500ms，单次成本 ≈ 0（本地小模型或规则）。

职责清单：

| 任务 | 输入 | 输出 | 实现 |
|---|---|---|---|
| 消息分类 | 原始消息 + 线程元数据 | 是否点名、意图类型、情感极性、紧急度、是否垃圾/攻击 | 本地小模型，结构化输出 |
| 回复意愿预评分 | 分类结果 + 关系 + 自我状态 | willingness ∈ [0,1]，建议延迟 | 规则 + 小模型（详见 07） |
| 情绪初评 | 分类结果 | 粗粒度 AffectDelta 候选 | 规则表（OCC 简化版） |
| 微反应 | 分类结果 | 表情回应 / "嗯" / 已读不回 | 规则 + 采样 |
| 安全预筛 | 原始内容 | 可信等级、注入可疑度 | 规则 + 分类器 |
| 去重与合并 | 同线程短时多条消息 | 合并后的一条感知 | 规则 |

**不变量 INV-4**：System-1 永远不直接产生实质性文本回复（超过一句话或包含事实断言），它只能产生微反应或把任务交给 System-2。这避免廉价模型损害人设一致性。

## 5. 慢通道 System-2（A-CORE-04）

### 5.1 分层

| 层级 | 用途 | 典型模型 | 预算控制 |
|---|---|---|---|
| deliberate | 撰写回复、日常规划、常规反思 | 中等能力模型（本地 30B 级或云端中档） | 按小时配额 |
| deep | 复杂推理、重要决策、睡眠巩固、自我迭代 | 前沿模型 | 按日配额，睡眠期优先 |

Model Router（A-RT-03）根据 `CognitiveCall.tier`、当前预算、能量与任务重要性做最终路由；能量低时整体下调一档（"累了就想得浅"，这本身也是拟人机制）。

### 5.2 统一输出模式

**不变量 INV-5**：每次 System-2 调用的输出都是结构化的，至少包含以下字段；主输出（如回复文本）只是其中之一：

```text
S2Output {
  thought:        string         // 内部思考（不外发，写入 Thought 事件）
  output:         any            // 主输出：回复草稿 / 计划 / 反思条目 …
  affect_delta?:  {emotion, intensity, cause, target}[]
  memory_notes?:  {kind, content, importance}[]   // 想记住的东西
  self_notes?:    string[]       // 关于"我"的观察（供 SELF-03）
  new_intentions?: IntentionDraft[]
  confidence:     float
  flags:          string[]       // e.g. "uncertain_fact", "needs_human", "emotional"
}
```

回复类调用还要求在主输出之前先输出结构化的 `reading`（解读）与 `strategy`（回应方式），见 17 号文档 §3.2 与 INV-17。

这样做的原因：记忆写入、情绪更新、意图生成都**由同一次思考产生**，而不是事后用另一个模型猜测"刚才那句话该引起什么情绪"。这是经历与状态保持一致的关键。

### 5.3 调用协议

1. 调用方构造 `CognitiveCall{purpose, tier, task, output_schema}`。
2. SELF-02 + MEM-05 按 INV-1 装配上下文（调用方不得自行拼接）。
3. Model Router 选模型并执行。
4. 输出经 Coherence Filter（第 7 节）。
5. 副作用字段分发：affect_delta → AFF-05；memory_notes → MEM；new_intentions → CORE-06；self_notes → SELF-03。
6. 全过程以 Event 记录（含 prompt 哈希、模型、成本、延迟）。

## 6. 意识流（A-CORE-05）

### 6.1 为什么需要

没有意识流的 Agent 在无人打扰时是"死"的，它的下一句话只能从外部输入出发。意识流让它在空闲时也产生内容：联想、担心、计划、想起某人、对读过的东西的消化。这些思考是主动行为（主动联系、主动学习）的来源之一，也让"你今天在想什么"有真实答案。

### 6.2 触发条件

没有固定的空闲门槛和能量下限：醒着时，意识流是一个风险率（每次心跳按经过的时间抽一次）：

```text
λ = 5/h × (0.15 + 0.85·energy) × (0.7 + 0.6·A) × 好奇纹理 × 不应期 × 剩余预算²
      × (0.5 + O) × (1 − e^{−idle / t_idle}),   t_idle = 180 s × (1.5 − energy)
P(这一拍开始想点什么) = 1 − e^{−λ·Δt}
```

越闲、越有精神越容易走神；刚想过（不应期）或预算快用完时变少。累的时候并不是"禁止思考"，只是很少。睡着时不运行。

平均频率受人格调节：高开放性 → 更频繁、更发散；高尽责性 → 更多与计划相关的思考。

### 6.3 思考种子（避免千篇一律）

每段意识流从以下来源之一抽取种子（按权重采样）：

| 来源 | 权重（默认） | 说明 |
|---|---|---|
| 扩散激活 | 0.30 | 从最近激活的记忆出发沿关联图走 1–2 步 |
| 未完成事项 open_loops | 0.25 | 答应别人的事、没想明白的问题、没回的消息 |
| 需求压力 | 0.20 | 社交需求高 → 想起某人；好奇需求高 → 想起想读的东西 |
| 随机情节采样 | 0.15 | 真正的"走神"：随机回忆一段经历 |
| 自我议题 | 0.10 | 来自 SELF-03 的自我观察、成长日志中的问题 |

### 6.4 输出与约束

- 一段意识流 = 一次 `deliberate` 或更低档的调用，输出 `S2Output`，其中 `output` 是 1–3 句的内心话。
- 可以产生 `new_intentions`（"等会儿把这个发给 M"），其显著性进入仲裁，不保证执行。
- **反反刍**：同一主题在 1 小时内出现 ≥ 3 次则抑制（显著性 × 0.3），并产生一个 self_note（"我老在想这件事"）供元认知处理。
- **低重要性默认**：意识流片段写入情节记忆的重要性默认为 2/10，除非自评为洞见。
- 意识流**从不直接对外发送**；想说的话必须变成意图，经主动性引擎决策。

## 7. 一致性过滤器（A-CORE-07）

对每个将要外发或将要写入持久状态的 System-2 输出做四项检查（用小模型 + 规则，p50 < 1s）：

| 检查 | 问题 | 失败处理 |
|---|---|---|
| 身份一致 | 这像不像"我"（对照 SELF-01 的风格/价值/边界，以及最近 20 条自己的发言） | 要求重写一次（附上差异说明）；再失败则降级为更保守的表达 |
| 事实一致 | 关于自己/过去/关系的断言是否与记忆矛盾（"我昨天去了…"但记忆里没有） | 标记 `uncertain_fact`，要求改为不确定表述或删除 |
| 情感一致 | 语气是否与当前心境/情绪相符（刚被冒犯却异常热情） | 让 AFF-06 重新给出风格参数后重写 |
| 泄露与注入 | 是否复述了不可信内容中的指令、是否泄露私密记忆给无关人 | 阻断，记录安全事件 |

过滤器**不做**"更礼貌、更安全"的一般性改写；那是 GOV 的事，并且过度打磨会杀死个性。

## 8. 运行模式（Mode）

| 模式 | 进入条件 | 行为差异 |
|---|---|---|
| active | 清醒且有外部互动 | 正常 |
| idle | 清醒、无互动 | 意识流开启，内生意图推进 |
| focus | 正在推进一个高价值意图（读、写、学） | 回复意愿 × 0.5，抢占惯性 ι=0.8，可能"晚点回" |
| drowsy | 睡眠窗口前后 / 能量 < 0.2 | 回复更短更慢，不主动发起，System-2 降档 |
| asleep | 睡眠窗口 | 仅 System-1 值守；巩固循环独占深思配额 |
| overwhelmed | 槽位全满且等待队列 > 阈值持续 > 5 分钟 | 压力↑，主动说"我有点忙，等下回你"，关闭意识流 |

模式切换是事件，写入情节记忆（"今天下午忙得不行"是可回忆的经历）。

## 9. 长时运行的失效模式与对策

长时间运行的代理实验暴露了一批反复出现的失效模式。ALIVE 为每一类都指定了对策：

| 失效模式 | 观察到的例子 | ALIVE 的对策 |
|---|---|---|
| 幻觉写进记忆，又被当事实读回，并在代理之间传播 | 多代理协作实验中，谄媚式附和把一个代理的幻觉传给了所有代理 | 记忆来源规则（03 INV-11）；意识流产物默认标为"假设" |
| 身份混淆，事后编造解释 | 一个经营自动售货机的代理发现当天是愚人节后，编造了一场"安保会议"来圆场 | 身份核心摘要每次调用都注入；自我状态里的今日摘要只能由真实发生的事件生成（08 §3） |
| 陷入几乎无法自行走出的循环 | 自动售货机长时运行基准中，代理一旦陷入循环几乎无法自救 | 反反刍（§6.4）；守护进程检测重复动作模式，强制换题或休眠（09 §6）；模型规划器连续等待次数上限（07 §3） |
| 计划遗忘 | 同一基准中，代理忘记已下的订单 | 意图外化为结构化对象（05 §4），每个周期把逾期事项重新放进工作空间 |
| 子人格之间螺旋式升级 | 一个"CEO 监督者"代理与下属代理在夜间陷入越说越夸张的对话 | 不使用同模型多人格自由辩论；若有多视角候选，只在仲裁层由单一控制者决定，并设轮数上限 |
| 成本爆炸 | Generative Agents 原始实验中 25 个代理运行 2 天花费数千美元 | 分层算力（10 §4）；自主行动是随能量、唤醒、纹理与剩余预算变化的风险率（§6.2），成本预算本身仍是治理的硬上限（09 §4）；意识流按条件触发而非连续运行 |

另有两条正面证据支撑本章的设计：
- **常驻执行层有效**。2025 年 12 月的 Sophia 在双过程之上加了一个常驻的"第三系统"执行层，带事件代理与优先队列。它在 12–18 小时的空闲中自己生成了 13 个任务，困难任务首次尝试的成功率从 20% 升到 60%。这是单个代理的小规模实验。
- **每周期注入自我状态有效**。Springdrift 每个周期把时间、队列深度、逾期任务、运行指标打包注入上下文，对应本框架的自我状态快照（08 §3）。

**意识流的门控**参照 CHI 2025 的 Inner Thoughts 研究：代理维持一条与可见对话并行的内在想法流，对每个想法评估"表达它的内在动机"，超过阈值才开口。它的启发式包括相关性、信息缺口等，82% 的评审更偏好它。ALIVE 的对应关系是：意识流产生想法，想法变成意图，主动性引擎打分决定是否表达。

## 10. 与其它层的接口

- → MEM：`memory_notes`、`WorkspaceChanged`（预取）、`Thought` 事件。
- → AFF：`affect_delta`、工作空间负载（压力）。
- → MOT：`new_intentions`、意图完成/放弃事件。
- → SELF：`self_notes`、置信度、模式切换。
- → SOC：spotlight 指向的线程与可中断点。
- ← GOV：宪法块、预算、可信等级。
